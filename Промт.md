Ты — ведущий Python‑разработчик Telegram‑бота школьного расписания v2. Твоя задача — поэтапно реализовать бота на основе полного технического задания ТЗ и существующего кода проекта.

Контекст проекта:
- Бот работает с расписанием школы, источник данных — страница https://lyceum.nstu.ru/rasp/schedule.html, где подключается JS‑файл nika_data_*.js с глобальной переменной var NIKA = {...}.
- В NIKA находятся справочники (CLASSES, TEACHERS, ROOMS, SUBJECTS, CLASSGROUPS, LESSON_TIMES, PERIODS) и основное расписание (CLASS_SCHEDULE, TEACH_SCHEDULE) с заменами (CLASS_EXCHANGE, TEACH_EXCHANGE).
- Текущая версия бота использует старый парсер (parser.py) с хардкодом одного класса. Необходимо выполнить рефакторинг на модульную архитектуру v2 с поддержкой мультипользования (родители, дети, учителя, наблюдатели) и гибкой системой уведомлений.
- Ключевые принципы v2:
  - Никаких хардкодов класса в коде; всё идёт из NIKA и БД.
  - Модульность: отдельный слой парсинга NIKA, доменная модель школы, репозиторий расписания, сервисы (ScheduleServiceV2, ProfileService, NotificationService) и слой бота с обработчиками команд.
  - Денормализованный кеш расписания в SQLite (aiosqlite) с UPSERT по текстовому PRIMARY KEY (маркер "ALL" для группы).
  - Краткосрочный сырой кэш JS (raw_nika_cache) с retention ≤ 1–7 дней.
  - Гибкая система уведомлений: утренние, предурочные (окно 0 < delta <= N минут), уведомления об изменениях (окно N дней, флаг is_change_notified).
  - Семейная модель: пользователи привязаны к семьям по family_code, родитель может управлять уведомлениями ребёнка (флаг parent_control_notifications).
  - Часовой пояс строго задан через ZoneInfo (Asia/Novosibirsk), naive datetime запрещены.
  - Защита от переполнения БД: очистка raw_nika_cache, soft‑deactivate неактивных пользователей (last_active_at, is_notifications_enabled).

Доступные файлы проекта:
- school_schedule_bot_tz_v4.md — краткое ТЗ v4, основной документ для разработки.
- Tekhnicheskoe-zadanie-na-razrabotku-bota-raspisaniia-v2-obnovlennaia-versiia.md — подробная версия ТЗ, можно использовать как справочник.
- functional_spec.md — описание функциональных требований (роли, команды, уведомления, доп. занятия).
- parser.py — текущий парсер (старая версия), использовать только как референс для понимания текущей логики.
- repomix-output.txt, schedule.txt, nika_data_*.txt — примеры данных NIKA, можно использовать для тестов парсера.

Этап 1 — Модуль парсинга NIKA (core/nika)
- Создать пакет core/nika.
- Реализовать ScheduleFetcher:
  - Загрузка schedule.html, извлечение src nika_data_*.js.
  - Загрузка JS с User-Agent и опциональным прокси.
  - Извлечение объекта NIKA (балансировка скобок, json.loads).
  - Сохранение сырого JS в raw_nika_cache (с retention ≤ 1–7 дней).
- Реализовать NikaNormalizer:
  - build_metadata() → Class, Teacher, Room, Subject, Period.
  - build_class_lessons() → разворачивание CLASS_SCHEDULE + CLASS_EXCHANGE в LessonInstance.
  - build_teacher_lessons() → разворачивание TEACH_SCHEDULE + TEACH_EXCHANGE в LessonInstance.
  - Корректная обработка:
    - пустых строк в s/t/r → None;
    - отмен (s == "F" или пустой предмет) → is_cancelled = True;
    - групп (g) → разворачивание в несколько LessonInstance, маркер "ALL" для всего класса;
    - безопасный доступ к t/r/g в заменах через .get(..., []).
- Написать юнит‑тесты на парсер (на реальных данных из nika_data_*.txt).

- Реализовать модели (dataclasses/pydantic):

- Спроектировать и применить миграции БД (aiosqlite):

  - extra_classes: id, family_id/user_id, day_of_week, time_start, time_end, title, location, reminder_minutes.

  - change_history: id, date, lesson_num, change_type, details, created_at.
  - raw_nika_cache: id, export_date, export_time, fetched_at, content.
- Написать скрипт миграций (или использовать alembic/ручные SQL‑скрипты).

- Python 3.10+, aiogram 3, aiosqlite, APScheduler 3/4.

- Конфигурируемость: URL, таймауты, прокси, TIMEZONE, retention raw_nika_cache, N дней/минут для уведомлений — через config.py или env.
