==================================================
1. ГЛАВНЫЙ ПРИНЦИП
==================================================

Карточка расписания должна позволять мгновенно ответить на вопрос:

ДЛЯ УЧЕНИКА:
«Что у меня? Когда?»

ДЛЯ ПРЕПОДАВАТЕЛЯ:
«У кого? Где? Когда?»

Поэтому информационная иерархия зависит от типа пользователя.

STUDENT MODE:

1. Время
2. Номер урока
3. Предмет
4. Преподаватель
5. Группа
6. Кабинет

TEACHER MODE:

1. Время
2. Номер урока
3. Класс
4. Группа
5. Кабинет
6. Предмет

Ключевые элементы должны иметь визуальный вес.
Вторичная информация должна быть заметно спокойнее.

==================================================
2. БАЗОВАЯ ГЕОМЕТРИЯ КАРТОЧКИ
==================================================

Каждая lesson card состоит из трёх зон:

┌────────────┬─────────────────────────────┬────────┐
│ TIME       │ MAIN CONTENT                │ ROOM   │
│            │                             │        │
│ 14:00      │ Предмет                     │  [305] │
│ 14:40      │ преподаватель · группа 2    │        │
│ УРОК 4     │                             │        │
└────────────┴─────────────────────────────┴────────┘

ЗОНА 1 — TIME:

Фиксированная ширина.

Содержит:

14:00
14:40
УРОК 4

Правила:
- start time — самый заметный элемент этой зоны;
- end time — меньше и светлее;
- номер урока — отдельной строкой;
- номер урока жирный;
- вся time-zone имеет одинаковую ширину у всех карточек;
- изменение ширины карточки из-за длинного текста запрещено.

Ориентир для mobile 390–430 px:
примерно 68–78 px.

--------------------------------------------------

ЗОНА 2 — MAIN CONTENT

Основная область карточки.

STUDENT MODE:

Предмет
Преподаватель · Группа 2

Пример:

Математика
Хорошилов М.С. · Группа 2

Предмет:
- крупный;
- bold/semibold;
- основной цвет;
- одна строка;
- автоматически уменьшать размер шрифта при необходимости,
  чтобы длинное название по возможности помещалось в одну строку;
- НЕ переносить название предмета на 2 строки,
  если его можно вместить адаптивным уменьшением размера.

Преподаватель:
- маленький;
- серый;
- спокойный;
- italic;
- secondary information.

Группа:
- маленький secondary text;
- серый;
- через разделитель «·»;
- пример:
  «Петрова Е.В. · Группа 2»

Группа не должна визуально конкурировать с предметом.

--------------------------------------------------

ЗОНА 3 — ROOM

Кабинет никогда не отображается обычным текстом.

Использовать отдельный визуальный badge / square.

Пример:

┌──────┐
│ 305  │
└──────┘

или:

╭──────╮
│ 305  │
╰──────╯

Требования:
- визуально самостоятельный объект;
- rounded square / rounded rectangle;
- достаточно крупный;
- bold;
- высокий контраст;
- фиксированная ширина;
- одинаковое положение во всех карточках.

Для длинных значений:
[спортзал]

Badge может становиться немного шире,
но не должен ломать сетку.

Пример обычной карточки:

│   │ 17:20                                  │
│   │ УРОК 4                                 │
│   │                                         │

│   │ Потапова М.В. · Группа 2         │305 │ │
│   │                                  └────┘ │
└─────────────────────────────────────────────┘

Визуальный приоритет:

Биология
████████████████

Потапова М.В. · Группа 2
────────────────────────

[305]

==================================================
4. ОДИН ПРЕДМЕТ ДЛЯ НЕСКОЛЬКИХ ПОДГРУПП
==================================================

КРИТИЧЕСКОЕ ПРАВИЛО.

Если несколько подгрупп одновременно изучают ОДИН И ТОТ ЖЕ
предмет, предмет НЕЛЬЗЯ дублировать.

Например:

Англ. язык

Группа 1:
Победа А.А. · Группа 1 · [230]

Группа 2:
Погорцева Г.К. · Группа 2 · [324]

Правильно:

┌─────────────────────────────────────────────┐
│ 2 │ 14:55                                  │
│   │ 15:35                                  │
│   │ УРОК 2                                 │
│   │                                         │
│   │ Англ. язык                              │
│   │ Победа А.А. · Группа 1          [230]  │
│   │ Погорцева Г.К. · Группа 2        [324]  │
└─────────────────────────────────────────────┘

Предмет показывается один раз.

Под предметом идут строки подгрупп.

Каждая строка содержит:

Преподаватель · Группа              [Кабинет]

Шрифт строк меньше предмета.

Кабинеты выровнены по правому краю.

Не создавать отдельные карточки для каждой подгруппы.
Это одна временная ячейка одного урока.

==================================================
5. РАЗНЫЕ ПРЕДМЕТЫ У ПОДГРУПП
==================================================

Если одновременно проходят РАЗНЫЕ предметы,
внутри одной lesson card показываются 2 блока.

Например:

УРОК 2
14:55–15:35

Группа 1
Ин. язык
Корчмит О.О. · Группа 1        [324а]

──────────────────────────────

Группа 2
Программирование
Гурина А.А. · Группа 2         [301]

Структурно:

┌─────────────────────────────────────────────┐
│ 2 │ 14:55                                  │
│   │ 15:35                                  │
│   │ УРОК 2                                 │
│   │                                         │
│   │ Ин. язык                        [324а] │
│   │ Корчмит О.О. · Группа 1                │
│   │ ─────────────────────────────────────  │
│   │ Программирование                 [301] │
│   │ Гурина А.А. · Группа 2                 │
└─────────────────────────────────────────────┘

Правила:
- номер урока и время отображаются один раз;
- это одна lesson card;
- внутри может быть 2–3 subgroup blocks;
- разделитель между блоками очень тонкий;
- не использовать громоздкие вложенные карточки;
- каждый блок должен легко сканироваться.

==================================================
6. РЕЖИМ КОНКРЕТНОГО РЕБЁНКА
==================================================

Если выбран конкретный ребёнок,
показывается в расписании только его подгруппа.

Например:

Ребёнок:
Лиза
6а · Группа 2

Урок:

2    14:55
     15:35
     УРОК 2

     Программирование
     Гурина А.А.           [301]

Группа полностью скрывается из вывода расписания.

Не показывать пользователю лишнюю подгруппу.

Таким образом:

CLASS VIEW
→ показывает весь класс.

STUDENT VIEW
→ показывает только relevant subgroup.

==================================================
7. TEACHER MODE
==================================================

Для преподавателя информационная иерархия другая.

Основная информация:

КЛАСС · ГРУППА
КАБИНЕТ

Предмет — вторичный.

Пример:

┌─────────────────────────────────────────────┐
│ 4 │ 16:40                                  │
│   │ 17:20                                  │
│   │ УРОК 4                                 │
│   │                                         │
│   │ 6а · группа 1                     [201] │
│   │ Биология                                │
└─────────────────────────────────────────────┘

Но если преподаватель одновременно ведёт
несколько классов/подгрупп в один урок,
все классы перечисляются В ОДНОЙ СТРОКЕ.

Например:

6а · группа 1, 6б · группа 2, 7а · группа 1        [201]

Ниже:

Математика

ВАЖНО:
не создавать отдельные карточки,
если преподаватель одновременно ведёт несколько классов.

Одна временная ячейка = одна карточка.

==================================================
8. ГРУППА В TEACHER MODE
==================================================

Группа должна быть визуально слабее класса,
но иметь примерно тот же размер шрифта.

Например:

6а · группа 2

где:
6а = основной акцент
группа 2 = серый

Но группа НЕ должна превращаться в маленький italic text.

Пример:

6а · группа 2
────────
Математика

==================================================
9. ПРЕДМЕТ В TEACHER MODE
==================================================

Предмет secondary.

В student mode:

БИОЛОГИЯ
Потапова М.В. · Группа 2

В teacher mode:

6а · Группа 2                 [305]
Биология

Таким образом один и тот же reusable component
меняет информационную иерархию,
но НЕ меняет общий визуальный язык.

==================================================
10. ДЛИННЫЕ НАЗВАНИЯ ПРЕДМЕТОВ
==================================================

Предмет должен стремиться помещаться в одну строку.

Например:

«Основы естественно-научных исследований»

не должен автоматически занимать 2–3 строки.

Использовать адаптивную типографику:

normal:
20–22 px

medium:
18–20 px

long:
16–18 px

very long:
14–16 px

Но минимальный размер подобрать так,
чтобы текст оставался читаемым.

Приоритет:
одна строка > перенос.

Не использовать `overflow: hidden`
с потерей текста.

Полное название должно оставаться доступным
по accessibility / tap details,
если визуально оно сокращено.

==================================================
11. ОКНА У ПРЕПОДАВАТЕЛЯ
==================================================

«Окно» — это отсутствие урока.

Не показывать окно как большую стандартную lesson card.

Использовать compact muted card.

Например:

┌──────────────────────────────────────────┐
│ 3 │ 15:50–16:30                         │
│   │ Свободное время                                │
└──────────────────────────────────────────┘

Или ещё компактнее.

Правила:
- существенно ниже обычной карточки;
- светлый muted background;
- нет большой room badge;
- нет тяжёлого визуального акцента;
- хорошо видно, где свободное время преподавателя.

Цель:
за один взгляд видеть структуру рабочего дня.

==================================================
12. ИЗМЕНЕНИЯ РАСПИСАНИЯ
==================================================

Изменённая карточка должна сохранять исходную геометрию.

Меняется только semantic accent.

ОБЫЧНАЯ:

синяя левая граница.

ИЗМЕНЁННАЯ:

оранжевая левая граница.

ОТМЕНА:
красная левая граница.
легка заливка всей карточки в красновытый оттенок
зачеркивание аккуратной красной линией всего текста (предмет, преподаватель, группа), вывод кабинета убираем

Оранжевым также подсвечивается
ТОЛЬКО изменившийся объект.

Например, если изменён кабинет:

Предмет
Учитель
                 [305] → [214]

`214` orange.

Если изменён учитель:

Потапова М.В. → Петрова Е.В.

только новая/изменившаяся часть orange.

Если изменён предмет:

Биология → История

«История» orange.

Не окрашивать весь текст карточки в orange.

На карточке можно показывать небольшой:

[Изменение]

При тапе открывать историю изменений.

историю иземенений на карточке не показывваем, тоько текущий измененный обьект

==================================================
13. ДОПОЛНИТЕЛЬНЫЕ ЗАНЯТИЯ
==================================================

Дополнительные занятия остаются в общем timeline.

Но имеют отдельную semantic color:

PURPLE.

Обычная карточка:
blue.

Изменённая:
orange.

Дополнительная:
purple.

Не смешивать эти состояния.

Доп:
- purple left border;
- light purple background;
- badge «доп.»;
- room badge остаётся отдельным квадратом.

==================================================
14. ОТМЕНЁННЫЙ УРОК
==================================================

Использовать red semantic state.

Пример:

11    17:30
      18:10
      УРОК 11

      Математика

Визуально:
- красная левая граница;
- очень светлый red tint;
- cancelled subject может быть зачёркнут;
- второстепенная информация приглушена.

Не удалять урок из временной последовательности:
пользователь должен понимать,
что в это время урок был запланирован,
но отменён.
Кабинет не показываем

==================================================
15. ТЕКУЩИЙ УРОК
==================================================

Добавить лёгкое состояние CURRENT.

Не делать карточку огромной.

Например:
- небольшой badge «Сейчас»;
- слегка усиленная граница;
- subtle background;
- возможно небольшой indicator рядом с временем.

Главное:
текущий урок должен быстро находиться глазами,
но не нарушать плотность списка.

17. НЕДЕЛЯ
==================================================

Неделя должна быть максимально компактной.

Не использовать огромные calendar tiles.

Например:

ПН 28.09       6 уроков · 3 доп.
ВТ 29.09       6 уроков · 1 изменение
СР 30.09       5 уроков · 1 доп.
ЧТ 01.10       6 уроков · 2 доп.
ПТ 02.10       7 уроков · 1 изменение

Semantic markers:
purple = допы
orange = изменения
red = отмены

Tap по дню → day view.

Навигация:

← Пред. нед.   Текущая   След. нед. →

18. ADAPTIVE / MOBILE-FIRST
==================================================

Основной viewport:

390 × 844 px

Также обязательно проверить:

375 × 812
393 × 852
430 × 932

Целевое требование:

На экране должно быть видно минимум 8 уроков
при обычной длине карточки.

Чтобы это обеспечить:

- минимизировать vertical padding;
- не делать большие заголовки;
- не делать giant cards;
- вторичная информация компактная;
- time zone компактная;
- room badge компактный;
- окна ещё компактнее.

Но:
текст не должен становиться нечитаемым.

Минимальные touch target:
44 × 44 px.
